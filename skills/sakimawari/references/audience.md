# 相手別の重視点（仮説）

この表は研究の結果ではなく、初版の仮説である。実際に出た質問と照らして、使いながら直す。

相手の情報が渡されたときだけ、重さの調整に使う。相手の情報が渡されていないときは、一般的な聞き手を想定し、この表を根拠に相手を決めつけない。

## 使い方

1. 渡された相手の情報（役職、案件への理解度、気にする点）に近い行を選ぶ。
2. その行の「重視しやすい点」に関わる穴を、同じ重さの中で先に並べる。重さの段は変えない。
3. 「案件への理解度」が低い相手には、用語の未定義と前提（型4、11）を拾いやすくする。理解度が高い相手には、経緯の説明不足を重く見ない。
4. 渡された情報と食い違う場合は、渡された情報を優先する。

## 相手の例

| 相手 | 重視しやすい点 | 拾いやすい型 |
|---|---|---|
| 上司・決裁者 | 判断すべきこと、期限、費用、リスク | 11 目的・問いの不在、9 実行面の抜け、5 代替案の不在 |
| 他部署 | 自分への影響、依頼内容、期限 | 8 課題と施策のずれ、9 実行面の抜け、6 範囲・条件の抜け |
| 顧客 | 効果、費用対効果、導入の負担、リスク | 2 比較対象の欠落、3 数字の出どころ、10 断定の強さのずれ |
| 聴衆（発表） | 前提知識、用語、結論の分かりやすさ | 11 目的・問いの不在、4 隠れた前提 |
| 専門家・レビュアー | 根拠、方法、再現性 | 1 飛躍、3 数字の出どころ、7 内部の不整合 |
| 案件に初めて触れる人 | 背景、用語、経緯 | 4 隠れた前提、11 目的・問いの不在 |
| 実行する人（申請する人、入力する人） | 自分の手間、やり方が変わる点、できない場合の扱い | 15 前提の崩れ・副作用、9 実行面の抜け、6 範囲・条件の抜け |
| 影響を受ける人 | 自分への影響、事前の知らせ、元に戻せるか | 15 前提の崩れ・副作用、9 実行面の抜け |

## 注意

- 相手を一つの型に決めつけない。「部長」でも、案件に詳しい人もいれば初見の人もいる。
- 相手の情報にない事情（過去の経緯、個人的なこだわり）は、推測として出力の2番に分けて書く。
