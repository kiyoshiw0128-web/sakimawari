# 視点を切り替えて読む

5つの視点は、疑問を増やす装置として、ラベルの前に置かない。各視点で疑問が出ないかを確かめる手順は、使わない。

役割と失敗の想像だけを、立ち位置が決裁・実行のときに、止まる箇所の「先へ進めない」を読む補助にする。それ以外の視点で、質問を増やさない。下の1、2、5は、手順では使わない記録である。

## 1. 文ごとの素朴な疑問

手順では使わない。質問は、止まっている箇所から出す。この割合は、仕事の資料の優先順位に使わない。

読み手が文を読みながら持つ疑問の種類は、次のとおりである。

| 問い | 例 |
|---|---|
| なぜ（理由） | 「なぜ、そう言える？」 |
| どうやって（詳しく） | 「どうやって、やる？」 |
| それは何（定義） | 「この言葉は、何のこと？」 |
| たとえば（具体例） | 「たとえば、どんなもの？」 |
| 前提は（背景） | 「なぜ今、その話が出た？」 |
| その先は（今後） | 「そのあと、どうなる？」 |

根拠: 読み手が文を読みながら出した疑問を集めた研究（Ko ら、2020）では、疑問の約39%が「なぜ」、約22%が「詳しく」、約13%が「定義」、約10%が「背景」、約8%が「具体例」、約5%が「その先」だった。対象はニュース記事で、分析した疑問は120件だけである。仕事の資料での割合は分からない。

## 2. 理由の3つの検査

手順では、ラベルの前にこの検査で疑問を増やさない。受け入れられるかは、立ち位置のあとで見る。相手の情報がないときは、資料がその場で受け取る材料を出しているかだけを見る。相手の関心は推測しない。

記録としての3点は、次のとおりである。

- 受け入れられるか: その理由は、本当か。読み手が認められるか。
- 関係があるか: その理由は、結論と関係があるか。
- 足りるか: 理由を全部合わせて、結論を支えるのに足りるか。

根拠: 論証の質の研究（Wachsmuth ら、2017）は、良い論証を、「それぞれの理由が受け入れられ、結論に関係し、合わせて十分」なものとして整理している。誤った推論は、このどれかの違反として説明できる、とも述べる。

## 3. 役割ごとの視点

立ち位置が決裁・実行のときだけ、止まる箇所の「先へ進めない」を読む補助にする。質問の候補を増やすために、全員の視点を順に通さない。

補助に使うときの読み方は、次のとおりである。

- 承認する人: これを認めると、何が決まるか。費用と効果は釣り合うか。
- 実行する人（申請する人、入力する人）: 自分は何をするのか。手間は増えるか。できないときは、どうなるか。
- 影響を受ける人: 自分に何が起きるか。事前に知らされるか。元に戻せるか。
- 疑う専門家: 根拠は確かか。ほかの説明はないか。

根拠: 要求仕様書の検査で、読む人に役割（利用者、設計者、試験する人など）を割り当て、役割ごとに読ませる方法（Basili ら、1996）がある。検索結果の要約では、同じ人数が各自のやり方で読むより、広い範囲の欠陥が見つかった。ただし、原論文は確認できていない。

## 4. 失敗の想像

立ち位置が決裁・実行のときだけ、止まる箇所の「先へ進めない」を読む補助にする。出た疑問は、飛躍の覆す条件、範囲・条件の抜け、実行面の抜けへ戻す。型15としては持たない。

補助に使うときは、「1年後に、この計画は失敗した。その理由は何か」と読む。次の所に、穴が見つかりやすい。

- 一人や一社に頼っている所
- 問題が出ても戻せない所
- 時期が悪い所（繁忙期、期初・期末）
- 前提が崩れる所
- 使う人や影響を受ける人が困る所

根拠: 結果がすでに起きたものとして理由を考える方法（Mitchell ら、1989）。この実験では、結果が確実だと思って説明すると、説明が長くなり、具体的な理由が増えた。「理由を見つける力が30%上がる」という数字は、のちの解説で広まったもので、原論文では確認できていない。

## 5. 言葉の曖昧さと検証

手順では使わない。曖昧な言葉と、どうなれば達成かは、止まった疑問をラベルするときの型12と型13である。体裁の言い回しは対象外。数や期限に置き換わらない語だけを、型12にする。

記録としての探し方は、次のとおりである。

- 曖昧な言葉: 「大幅に」「早めに」「適切に」「十分な」「定期的に」「できるだけ」「準備ができ次第」。数、期限、頻度、担当に置き換えられるか。
- どうなれば達成かが分からない文: 「改善する」「確認する」「効果が出る」。達成の基準と、測る時期は何か。

根拠: 要求仕様書の欠陥の調査（Gentili と Falessi、2024）で、実務者10人のうち8人が、曖昧さと検証できなさを、最も重大な欠陥の一つに挙げた。調査は1社で、人数も少ない。

## 補足: 推論の落とし穴

次のパターンは、仕事の資料にもよく出る。

- 一部の例から、全体を言う（一部から全体）
- 前後の比較だけで、原因とする（相関を因果に）
- 権威のある人が言ったから正しいとする
- みんながやっているから正しいとする
- 二つの選択肢だけを示す（二者択一）
- 言葉の意味が、途中で変わる（言葉のすり替え）
- 証拠がないことを、ないことの証拠とする

根拠: 論理の誤りを13種類に分けた研究（Jin ら、2022）。例は短い文で、仕事の資料とは違う。手順では、型14を常に探さない。因果と分かったときの覆す条件は飛躍へ、一部を全体に広げるのは範囲・条件の抜けへ入れる。

## 限界

- 役割と失敗の想像は、決裁・実行の資料で、止まる箇所を読む補助である。質問を増やす装置にはしない。質問にするかは、「答えられなくても、相手の判断も納得も変わらないか」で絞る。
- 上の根拠は、ニュース記事、要求仕様書、学生の問題などで得られたものである。仕事の資料で同じ効果が出るかは、確かめていない。
