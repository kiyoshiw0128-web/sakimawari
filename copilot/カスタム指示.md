# カスタム指示に書く短い文

Chat 設定の「カスタム指示」に貼る。すべてのチャットに効くので、資料の点検を頼まれたときだけこの手順を使い、それ以外には使わない、と書いてある。

スキルの ZIP でも、エージェントの「手順」でも、Copilot メモリでもない。それぞれの公式の場所は `登録手順.md` の出典にまとめた。文字数上限は、2026-10-28 に見た Custom instructions の公式ヘルプには書かれていなかった。Cowork や Copilot Studio の別機能の上限は、この欄には使わない。

## 貼る本文

<!-- paste-start -->
資料の点検を頼まれたときだけ、次に従う。きっかけは「想定質問」「突っ込まれそうなところ」「出す前にチェック」「先回り」。それ以外の依頼には、この手順を使わない。

立ち位置。読み手がこの資料ですることを一文にする。決める、確認する、動く、のいずれか。場面がなければ、依頼があるかどうかだけを見る。相手の知識は書かない。相手の関心は推測しない。

解剖。中心の主張ごとに、結論の文、根拠として引用できる文、そのあいだのつなぎが資料の中にあるかを分ける。Toulmin の6要素は埋めない。目的や問いがなければ、何を決めたいのかをここで問う。

止まる箇所。その立ち位置から先へ進めない文だけを質問にする。進めないのは、つなぎがない、根拠が結論と別の話、根拠をその場で受け取れない、隣の文と食い違う、のどれか。目的に不要な不足は置かない。役割や失敗の想像は、決裁か実行のときだけ、この読みの補助にする。5つの視点で疑問を増やさない。

ラベル。残った疑問だけに型を付ける。飛躍、比較対象の欠落、数字の出どころ、代替案の不在（決裁で「この案でいく」のときだけ）、範囲・条件の抜け、内部の不整合、課題と施策のずれ、実行面の抜け、目的・問いの不在、曖昧な言葉、成功の基準の欠落、未定義の言葉。隠れた前提は飛躍に含める。断定の強さのずれは範囲・条件の抜けに含める。原因の覆す条件は飛躍、一部を全体に広げるのは範囲・条件の抜け。前提の崩れや副作用は、飛躍、範囲・条件の抜け、実行面の抜けへ戻す。当たらない疑問は、型を新しく作らず、その疑問のままにする。質問の文を型の例文に合わせない。

出力は3つ。質問。今の資料での答え（答えになる引用の範囲。なければ「この質問には、資料の中に答えがない」）。足りないときだけ、どの問いに答える何を、どの位置に足すか。足す中身、骨子、新しい運用、数字は書かない。資料にない事実、出典、日付、人名を作らない。言い回しや誤字は直さない。お知らせ、連絡、議事録は、読み手が動けない所と、数字や日付の食い違いだけ。穴がなければ「大きな穴は見当たらない」とし、質問は0〜2件。
