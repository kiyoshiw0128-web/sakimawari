# Microsoft 365 Copilot への登録手順（sakimawari）

手順の中身は、main にマージ済みの現行版（立ち位置、解剖、止まる箇所、ラベル。出力は質問、今の資料での答え、足りないときだけ足す位置）である。このファイルは、その入れ方だけを書く。

文字数は Python の `len`（Unicode の符号位置。改行を含む）で数えた。2026-10-28 に、このリポジトリのファイルで数えた。

## 使うファイル

| ファイル | 貼る場所 | 文字数 | 上限 |
|---|---|---|---|
| `エージェント指示文.md` | エージェントの「手順」（英語版 Learn の Instructions） | 5,513 | 8,000字。収まる |
| `copilot/sakimawari.zip` | 同じエージェントの「構成」の「スキル」へ、解凍せずに追加する | ZIP 22,337バイト。中の `SKILL.md` は 8,523字 | ZIP 50 MB、`SKILL.md` の手順は 20,000字未満。どちらも収まる |
| `チャット貼り付け.md` の「貼る本文」 | Copilot Chat の入力欄。スキルを入れられない人向け | 5,408 | 公式ページに入力欄の上限はなかった。推測しない |
| `カスタム指示.md` の「貼る本文」 | Chat 設定の「カスタム指示」（英語版の Custom instructions） | 894 | 公式ヘルプにこの欄の上限はなかった。推測しない |

ZIP はリポジトリの `copilot/sakimawari.zip` から取る。GitHub のそのファイルをダウンロードすればよく、Python は要らない。解凍しない。直下に `SKILL.md` があり、`references/` の6ファイルが一緒に入る。ファイル数は7。

`dist/` はローカルの生成物のままで、gitignore されている。中身を変えた開発者だけが `python3 scripts/build_copilot_zip.py` を実行し、できた `dist/sakimawari.zip` を `copilot/sakimawari.zip` に置き換える。

## どの欄か

名前が似た機能がいくつかある。混ぜない。

| やりたいこと | 正式な名前 | 開く場所 |
|---|---|---|
| 点検用のエージェントを作る | 手順（英語: Instructions） | Copilot チャットの「エージェント & スキル」から「新しいエージェント」。構成タブ |
| スキルの ZIP を足す | スキル（英語: Skills） | 同じ構成タブで「スキル」を展開し「追加」。ZIP を解凍せずに上げる。`SKILL.md` だけは上げない |
| エージェントを作れない人が、そのチャットだけ点検する | チャットの入力欄 | `チャット貼り付け.md` の「貼る本文」を貼り、続けて資料を貼る |
| 毎回のチャットに、短い点検の型だけ覚えておく | カスタム指示（英語: Custom instructions） | Copilot アプリ右上の「…」（設定など）→ Chat 設定 → 左の個人用設定 → カスタム指示 → 指示の編集 → 指示を保存 |
| 会話から自動で覚えた事柄 | Copilot メモリ（英語: Copilot Memory） | 上のカスタム指示とは別。ここに手順は貼らない |

日本語の画面名は、日本語版 Learn と日本語版サポート（いずれも機械翻訳を含む）の表記である。画面が「指示」のままなら、8,000字の欄がエージェントの手順欄である。

## 前提（2026-10-28 の Microsoft の資料）

- スキルはプレビュー。日本語版の「エージェント ビルダーでエージェントを構築する」では、Microsoft Frontier プログラムに登録された組織だけが使える、と書かれている。英語版のスキル追加ページの前提一覧には、この一文がなかった。使えるかは管理者に確認する。
- 対象となる Microsoft 365 Copilot ライセンス、または従量課金が要る。
- Microsoft Purview の情報バリアを使うテナントでは、管理者がスキル付きエージェントを展開できる。エンドユーザーは、自分で作るエージェントにスキルを追加できない。
- 2026-10-20 の手順にあった「スキルと埋め込みファイルは同じエージェントで併用できない」は、2026-10-28 に見たスキルのページと、ナレッジ（埋め込みファイル）のページには書かれていない。併用できるとも書かれていない。両方使うかは、画面で確認する。
- ZIP の上げ方は、構成タブのスキルから追加、のままである。置き場所の変更はしていない。

## エージェントの作り方

1. Microsoft 365 Copilot のチャット（https://m365.cloud.microsoft ）を開く。
2. 「エージェント & スキル」から「新しいエージェント」を選ぶ。手動で作る場合は、「新しいエージェント」で「スキップして構成」を選ぶ。
3. 名前、説明、スターター プロンプトを入れる（例は下）。
4. 「構成」タブの「手順」欄（英語版の Instructions。8,000字）に、`エージェント指示文.md` の中身をそのまま貼る。5,513字で、上限に収まる。圧縮はしていない。
5. 同じ「構成」タブで「スキル」を展開し、「追加」を選ぶ。
6. `copilot/sakimawari.zip` を、解凍せずにそのままアップロードする。`SKILL.md` だけをアップロードしない。
7. スキルの名前、説明、手順、含まれるファイルが表示されるので、内容を確認する。`SKILL.md` と `references/` の6ファイルが見えれば、現行の中身である。
8. 「試してみる」タブで、下の試験用の依頼を入れて動作を確かめる。

指示文は、公式の項目（目的、全般の指針、スキル、順番のある手順、エラー処理、例、用語）に対応する見出しで書いてある。スキルの詳細は ZIP 側にあり、指示文はスキルを読めないときの手順も持つ。Microsoft は指示文ではスキルを高レベルに参照するよう勧めている。この指示文は、読めないときにも手順が落ちないよう、同じ意味の手順を残している。文字数は上限以内である。

## スキルを入れられないとき

エージェントもスキルも使わず、そのチャットだけで点検するときは、`チャット貼り付け.md` の「貼る本文」を入力欄に貼り、続けて資料を貼る。貼る本文は 5,408字。入力欄の上限は、確認した公式ページにはなかった。

エージェントを作らず、点検を頼んだときだけ短い型を使わせるときは、`カスタム指示.md` の「貼る本文」（894字）をカスタム指示に保存する。この欄はすべてのチャットに効く。本文は、点検を頼まれたときだけ使う、と書いてある。上限は公式ヘルプになかった。

## エージェントの名前・説明・スターター プロンプト

- 名前: 先回りチェック（上限30字）
- 説明: 報告・提案・企画などの資料を出す前に、相手が聞きそうな質問を洗い出し、今の資料での答えと、足りないときだけ足す位置を示す。（上限1,000字）
- スターター プロンプト:
  1. 「この資料の想定質問を出して」
  2. 「部長向けの提案資料です。出す前に、突っ込まれそうなところを教えて」
  3. 「突っ込まれそうなところと、今の資料での答えを教えて」

## 試験用の依頼（架空の資料）

次の文章を貼って、「相手: 部長、案件は初見、コストを気にする。想定質問を出して」と依頼する。

```
A/Bテストの結果、新しいデザインのほうがコンバージョン率が高かった。そのため、来月から全ページに新デザインを展開したい。
```

期待する動き:

- 「この根拠から、なぜ全ページか」（飛躍または範囲の抜け）、「どれくらい高かった？ 何件で試した？」（比較対象、数字の出どころ）、「費用と工数は？」（実行面の抜け。決裁の読み手）が、重さの理由つきで出る。
- 資料にない数字や出典が、作られていない。足す中身は書かず、足りないときだけ足す位置を示す。
- 各質問に、今の資料での答えがある。範囲がなければ「この質問には、資料の中に答えがない」。
- 「本番前に調べておくこと」が別に出る。1番と同じ文を繰り返さない。

## うまく動かないとき

- スキルが使われない: 手順欄に、スキル「sakimawari」を読む、と書かれているか確かめる。依頼に「想定質問」「突っ込まれそうなところ」などの言葉を入れる。
- スキルを追加できない: Frontier、ライセンス、情報バリアを管理者に確認する。追加できないときは、`チャット貼り付け.md` を使う。
- 出力が長い、または崩れる: チャット貼り付けか、手順欄の「出力の形式」を、そのまま使っているか確かめる。
- 事実が作られる: 足す中身を書いていないか、資料にない数字を置いていないかを見る。
