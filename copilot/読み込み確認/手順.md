# Copilot がスキルのどのファイルを読んでいるかの確認

## 目的

Copilot が、スキルの `SKILL.md` と、`references` の中の補足資料を、実際にどこまで読んでいるかを調べる。

## 使うもの

- `dist/sakimawari_probe.zip`: 確認用のスキル。`python3 scripts/build_probe_zip.py` で作る。普通のスキルと中身は同じで、各ファイルに「読んだ印」の決まりが入っている。
- エージェント指示文は、いつものもの（`copilot/エージェント指示文.md`）を、そのまま使う。

## 手順

1. 確認用のエージェントを新しく作る（普通のエージェントは、そのまま残す）。
2. 指示欄に、いつもの `エージェント指示文.md` を貼る。
3. スキルに、`dist/sakimawari_probe.zip` を追加する。
4. 普通の資料で、「想定質問を出して」と依頼する。
5. 出力の**一番最後の行**を見る。「読んだ印: S H O」のように出る。

## 印の意味

| 印 | ファイル |
|---|---|
| S | SKILL.md |
| H | references/hole-types.md（穴の型の詳細） |
| A | references/audience.md（相手別の重視点） |
| O | references/output-format.md（出力の様式と例） |
| D | references/diagram-patterns.md（図の型） |
| L | references/lenses.md（視点を切り替えて読む方法） |
| R | references/sources.md（出典） |

## 結果の見方

- 全部の印が出る: 補足資料も読まれている。
- S だけ、または S と数個: 補足資料は、一部しか読まれない。読まれないファイルの大事な内容は、SKILL.md か指示文に入れる必要がある。
- 印が出ない、または最後の行がない: スキルそのものが、使われていない可能性がある。

## 注意

- 同じ資料でも、実行のたびに結果が変わることがある。2〜3回試すと確かである。
- 確認が終わったら、確認用のエージェントとスキルは削除する。普通の点検には、使わない。
- 出力の最後の行を、そのまま送ってもらえれば、結果から、スキルの作りを直す。
